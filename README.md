# LinkUp — Сервис подбора кандидатов по интересам (Лабораторная работа №1)

Данный проект представляет собой реализацию микросервисного сценария для продуктового трека **LinkUp** на языке Go. Проект построен с соблюдением принципов чистой архитектуры, внедрения зависимостей (Dependency Injection) и покрытия бизнес-логики unit-тестами.

---

## Назначение сценария и бизнес-правила

Сценарий **Discover (Рекомендации)** находит подходящих кандидатов для пользователя на основе общих интересов.

### Основные правила:

1. **Исключение себя:** Инициатор поиска (`subject`) не может быть рекомендован сам себе.
2. **Фильтрация неактивных профилей:** В выдачу попадают только пользователи с флагом `Active: true`.
3. **Совпадение по интересам:** У кандидата должен быть хотя бы один общий интерес с пользователем (точное сравнение строк).
4. **Уникальность ID:** Повторяющиеся интересы не приводят к дублированию ID кандидата в итоговом списке.
5. **Неизменность данных:** Функция обработки правил не модифицирует переданные входные структуры.

## Архитектура и структура проекта

Код структурирован по стандартному шаблону Go-проектов:

```text
linkup/
├── go.mod                     # Модуль проекта ([example.com/linkup](https://example.com/linkup))
├── cmd/
│   └── app/
│       └── main.go            # Точка входа: сборка зависимостей и демонстрационный запуск
└── internal/
    ├── discovery/             # Доменная логика и сервисный слой
    │   ├── model.go           # Доменная модель Profile
    │   ├── rules.go           # Чистая бизнес-функция Discover
    │   ├── service.go         # Сервисный слой и контракт чтения ProfileReader
    │   ├── rules_test.go      # Unit-тесты для чистой логики Discover
    │   └── service_test.go    # Unit-тесты сервисного слоя и обработки ошибок
    └── memory/                # In-memory реализация хранилища
        └── repository.go      # Реализация ProfileReader на данных в памяти
```
